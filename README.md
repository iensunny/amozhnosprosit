# а можно спросить?

Основной путь развёртывания — обычный Node.js-сервер и MySQL на VPS (например,
REG.RU). Интерфейс и API обслуживаются одним процессом. Docker и облачные
функции для этой конфигурации не нужны.

## Состав

- `public/` — статический интерфейс и брендовые изображения;
- `recovery/cloudflare-worker-2026-10-15.mjs` — сохранённая серверная логика;
- `server/` — Node.js API и адаптер MySQL;
- `database/mysql-schema.sql` — схема MySQL для VPS.

## Переменные окружения

Для запуска на VPS задайте `MAX_BOT_TOKEN` и параметры MySQL. Можно указать
одну переменную `DATABASE_URL` (`mysql://user:password@host:3306/database`)
или задать `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_USER`, `MYSQL_PASSWORD` и
`MYSQL_DATABASE` отдельно. Пароль храните в секретах сервера, не в Git.

Перед первым запуском создайте пустую базу MySQL и примените
`database/mysql-schema.sql`. Эта база не содержит предыдущих записей; если
нужные тестовые записи понадобятся, перенесите их отдельной проверяемой
миграцией.

`MAX_BOT_NAME` можно задать отдельно; по умолчанию используется имя бота,
указанное в серверном коде.

## Локальный запуск

```sh
npm install
npm start
```

Проверки адаптера базы:

```sh
npm test
```

## Диагностика

Сбор и готовые SQL-запросы для просмотра задержек запуска, ошибок API,
сценариев пары и попыток ежедневных уведомлений описаны в
[`docs/monitoring.md`](docs/monitoring.md). Срок хранения телеметрии — 7 дней.

## Развёртывание

Приложение развёртывается как Node.js-сервис на VPS. Для автоматического
развёртывания используйте секреты GitHub Actions; не добавляйте пароли и
токен MAX в файлы репозитория.
