# а можно спросить?

Основной путь развёртывания — один Node.js-сервис на VPS с локальной SQLite
базой в постоянном каталоге. Отдельный сервер базы и Docker не нужны.

## Состав

- `public/` — статический интерфейс и брендовые изображения;
- `recovery/cloudflare-worker-2026-10-15.mjs` — сохранённая серверная логика;
- `server/` — Node.js API и SQLite-адаптер к серверной логике;
- `database/sqlite-schema.sql` — схема SQLite (приложение также создаёт её при
  первом старте).

## Переменные окружения

Для запуска задайте `MAX_BOT_TOKEN`, `PUBLIC_APP_URL` и `SQLITE_PATH`. Убедитесь,
что у пользователя Node.js есть права на каталог базы. Сам файл базы храните
вне `public/` и включайте в резервное копирование. SQLite-файл создаётся
автоматически при старте. Существующие данные необходимо отдельно перенести и
сверить до переключения пользователей.

`MAX_BOT_NAME` можно задать отдельно; по умолчанию используется имя бота,
указанное в серверном коде.

## Локальный запуск

```sh
npm install
npm start
```

Проверки приложения и адаптера базы:

```sh
npm test
```

## Диагностика

Сбор и готовые SQL-запросы для просмотра задержек запуска, ошибок API,
сценариев пары и попыток ежедневных уведомлений описаны в
[`docs/monitoring.md`](docs/monitoring.md). Срок хранения телеметрии — 7 дней.

## Развёртывание

Приложение развёртывается как один Node.js-сервис на VPS. Для автоматического
развёртывания используйте секреты GitHub Actions; не добавляйте токен MAX в
файлы репозитория. База должна находиться на постоянном диске, вне публичного
каталога сайта.
